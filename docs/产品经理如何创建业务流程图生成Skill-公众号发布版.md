## 一、目标：本期 Skill 解决什么

网厅 / 证券业务里，流程图几乎总要出现在需求文档开头：谁在哪一步、过不过准入、要不要挽留、回炉怎么走。

痛点很具体：

- Visio / 墨刀画得漂亮，开发读不动，还要再誊一版  
- 纯 mermaid 能进文档，但拖不动、折弯难调、交叉泳道更别提  
- 流程改了三轮，图和正文经常对不上

所以我们做的不是「又一个在线绘图网站」，而是一条 **Cursor 技能**：

| 端 | 交付 |
|----|------|
| Agent | 听口述 / 看截图 → 落盘 mermaid `业务流程.md` |
| 本地画布 | 一期编辑器：图形、泳道、连线、快捷键；保存同步 json + mermaid |
| 同事 | 拷技能目录即可，不 pull 你们的业务仓库 |

**给谁用：** 产品、BA、解决方案——凡是要「先把流程说清楚、再交给开发」的人。

**和后续规划的关系：** 可挂进需求文档流水线（墨刀 → PRD → 飞书）里当「流程图章节」的上游；一期先把「独立可分享」做稳。

## 二、前置准备：把技能装进 Cursor

仓库公开地址：

https://github.com/tangjing2/biz-flow-gen

装法（Windows 示例）：

```bash
git clone https://github.com/tangjing2/biz-flow-gen.git
xcopy /E /I biz-flow-gen %USERPROFILE%\.cursor\skills\biz-flow-gen
```

拷完后目录里应能看到：

```text
biz-flow-gen/
  SKILL.md
  技能使用说明.md
  README.md
  editor/
  scripts/serve.mjs
  assets/editor-preview.png
```

新开一轮 Cursor 对话（或 Reload Window）。本机需要已安装 **Node.js**（用来起本地画布）。

更细的说明见仓库内《技能使用说明.md》。

## 三、过程主线：从一句话到可改的图

### 提词词 1 · 先把技能做出来（共建阶段）

*编者注：这一轮不是「用技能」，而是「把技能打包成可外发」。读者可跳过，直接看提词词 2。*

要点如下（节选）：

> 可以，开工，然后你生成好的「业务流程图生成技能」直接落到 `D:\网厅需求演示系统` 这个路径即可，跟之前的原型批注差不多一样。

当时边界已经定死了三件事：

1. **必须有给人看的《技能使用说明.md》**，和给 Agent 的 `SKILL.md` 分开  
2. **同事可以不 pull 业务仓库**——技能包自带一期编辑器 + `serve.mjs`  
3. **入料三项、产出两项**：口述或截图 + 目录 +（可选）标题 → `业务流程.md` + 编辑链接  

*编者注：如果技能还绑着 `caseId` / 开工单 / `pnpm dev`，同事一拷就废。独立 serve 才是「能分享」的分水岭。*

---

### 提词词 2 · 日常使用（读者跟练从这里开始）

对话里给齐三样即可：

```text
用业务流程图技能。流程：客户进介绍页 → 选销户原因 → 要挽留就进预约，否则准入校验 → 提交审核 → 结束。
落盘到 D:\demo\一站式销户，标题「一站式销户」。
```

也可以贴一张旧流程图截图，让 Agent 按图还原成泳道初稿。

**Agent 应回你两样：**

1. `{落盘目录}/业务流程.md` 的完整路径  
2. 本地编辑链接，例如 `http://127.0.0.1:8790/?dir=D:\demo\一站式销户`

自己起编辑器也可以：

```bash
node scripts/serve.mjs --dir "D:\demo\一站式销户" --port 8790
```

### 提词词 3 · 在画布里改完再说「同步文档」

改完泳道名、补了横行系统、拖了折弯之后：

```text
我已经在编辑器里保存过了，请根据最新的 业务流程.md，把需求文档里的流程图章节更新一下。
```

*编者注：技能本身只保证 md/json 落盘；「写进 PRD / 同步飞书」可以接你们已有的需求文档技能，不要让一个技能包揽天下。*

### 一期能力清单（自评从「能画」到「能改」）

| 能力 | 怎么用 |
|------|--------|
| 图形 | 开始/结束、处理、判定、批注 |
| 泳道 | 竖列≈角色、横行≈系统，可叠加；双击改名；Delete 删除 |
| 调宽高 | 拖泳道分割线 |
| 节点 | 拖拽；方向键按网格；Shift 多选 |
| 连线 | 四边端口拉线；中段折弯；双击改文字 |
| 快捷键 | Ctrl+Z/Y、C/X/V、S；Delete |
| 复位视图 | 只重置平移/缩放，不改图 |

交叉矩阵请在画布里加横行；mermaid 导出仍以竖向角色泳道为主——这是有意为之，方便开发扫读。

**踩坑记录（真实）：**

- 第一版若仍依赖业务仓 Vite，同事无法外发 → 抽成 `scripts/serve.mjs` + 自带 Vue  
- 带标签的边（`-->|是|`）解析曾丢文案 → 已修，销户类复杂图可完整还原  
- 端口不要和原型批注的 8788 抢；默认 8790，占用换 8791  

满意度自评：从「只能预览 mermaid」约 40 分，到「可独立改图并回写」约 **80 分**；剩余 20 分留给协同编辑、导出图片、更多图形等后续迭代。

## 四、体验与经验建议

1. **把 Agent 当搭档，不是自动贩卖机。** 流程口述含糊时，宁可让它追问「挽留成功去哪」，也不要硬生成一张假图。  
2. **三项入料缺一就停。** 没有落盘目录，就不要让它写到聊天窗口里当「完成」。  
3. **规则写回 SKILL.md。** 你们团队若固定「竖列=角色、横行=系统」，改技能说明，别每次口头强调。  
4. **mermaid 给开发，画布给自己。** 交叉泳道别硬塞进 mermaid 正文。  
5. **保存后再引用。** 需求文档、飞书同步，都以磁盘上最新的 `业务流程.md` 为准。  
6. **开源仓库当单一事实源。** 迭代编辑器时，改 `editor/` 并同步改使用说明里的能力表。  
7. **先本机跑通，再推荐同事。** 一条 `serve.mjs` 命令能打开画布，再发仓库链接。

## 附：完整提示词时间线（可复制）

**T1 · 安装后自检**

```text
请按 biz-flow-gen / 业务流程图技能，确认本机技能路径可用，并用任意空目录生成一张最小流程图（开始→处理→结束），返回 md 路径和编辑链接。
```

**T2 · 口述出图（日常）**

```text
用业务流程图技能。
流程：{用箭头写出步骤与判定}
落盘到：{绝对路径}
标题：{业务名}
```

**T3 · 贴图还原**

```text
按业务流程图技能，根据我贴的这张流程图截图，在 {绝对路径} 生成 业务流程.md，并打开本地画布链接。
```

**T4 · 仅起编辑器（已有 md）**

```bash
node scripts/serve.mjs --dir "{绝对路径}" --port 8790
```
